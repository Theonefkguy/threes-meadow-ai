# 合三 · Threes Meadow AI

[在线试玩](https://theonefkguy.github.io/threes-meadow-ai/) · [English](README.md) | **简体中文**

一个可以在浏览器里观看、随时接管的高性能 Threes 游戏 AI。结合多阶段时序差分学习（4 格与 5 格 N-tuple 查表）与六层期望搜索，使用概率剪枝控制计算量。模型完全在你的设备上运行，无需账号、API 密钥或推理服务器。

**6144 达成率 74.0% · 12288 达成率 11.7% · 网页 AI 在官方奖励牌周期规则下 4096 局测试。**

## 试玩

打开[游戏页面](https://theonefkguy.github.io/threes-meadow-ai/)，选择中文或 English，点击「AI 自动玩」。使用方向键、滑动或方向按钮即可手动接管。默认 V31 模型下载约 17 MB（解压后 32 MB），首次使用时下载并显示进度条；也可选择完整精度版（下载约 30 MB），它使用 32 位原始精度的 5 格表，而不是 16 位；4096 局配对测试中两者成绩相同（12288：9.8% 对 9.9%，91% 的对局每一步都相同，见 [V42](RL-V42-PRECISION.md)）；另外还可切换到第四版或经典搜索进行对比。

## V43：从第一步起用六层搜索

V41 只在棋盘出现 6144 之后才用六层搜索。从第一步起就用（剪枝阈值 0.005，每步最多 400 ms），中盘也明显受益。4096 局配对整局，种子和权重与 V41 相同：

| 指标 | 6144 前 5 层、之后 6 层（V41） | 全程 6 层（网页） |
|---|---:|---:|
| 合出 3072 | 96.7% | 97.0% |
| 合出 6144 | 67.9% | **74.0%** |
| 合出 12288 | 9.9% | **11.7%** |
| 6144 之后合出 12288 | 14.5% | 15.8% |
| 平均得分 | 659,680 | **704,718** |

两项主要比较经 Holm 校正后均显著（6144 +6.1 个百分点，p=1.4×10⁻⁹；12288 +1.8 个百分点，p=0.007）。原生搜索每步慢约 2.8 倍；桌面浏览器在 1536–6144 阶段的局面上平均每步 24–28 ms（P95 44–57 ms）。[V43 报告](RL-V43-EARLY-DEPTH.md)

## V41：6144 之后加深搜索

棋盘出现 6144 之后，网页 AI 改为往前搜 6 步、剪枝更细（阈值 0.005，原为 5 步、0.01），每步最多 400 ms。4096 局配对整局（网页实际下载的 float16 权重，官方奖励牌周期，两组在第一次合出 6144 之前完全相同）：

| 指标 | 6144 后 5 层 | 6144 后 6 层（网页） |
|---|---:|---:|
| 合出 6144 | 67.9% | 67.9% |
| 6144+3072+1536+768 同时在场 | 24.2% | 30.7% |
| 合出 12288 | 6.5% | **9.9%** |
| 6144 之后合出 12288 | 9.5% | **14.5%** |
| 平均得分 | 624,319 | **659,680** |

合出 12288 多 3.4 个百分点（精确 McNemar p=1.4×10⁻⁹）。主要来自加深（从首次 6144 起只加深：+3.4 个百分点；只调细剪枝：+1.1，不显著），两者一起效果最好。桌面浏览器在这一阶段平均每步 29 ms（P95 62 ms）；较慢的设备在时限内搜不完 6 层时，使用已搜完的 5 层结果。该设置下 JS 与 C++ 在 320 个局面上走法完全一致。此前改进第 3 段评分表的尝试（V27–V38）都没有效果；V39 诊断显示，失败大多发生在攒最后一张 768 的阶段，而不是最后的合并。

## V35：官方奖励牌周期

官方 app 不是每张来牌独立有 1/21 的机会出奖励牌，而是每 21 张来牌恰好出一张。我们让 AI 在 iPhone 上自动玩了两整局官方游戏来验证：148 个完整的轮次，每轮都恰好一张奖励牌（见 [RULES.md](RULES.md)）。网页引擎已改用这个规则；默认 AI 根据看到的来牌跟踪周期：本轮奖励牌已出就不会再出，否则概率为 1/(21 − 已排除的位置数)。

同一批种子，每组 4096 局完整对局，V31 模型，网页五层搜索：

| 指标 | 旧规则（V31 上线检查，2048 局） | 周期规则，AI 不知道周期 | 周期规则，AI 知道周期 |
|---|---:|---:|---:|
| 合出 1536 | 98.6% | 99.4% | 99.3% |
| 合出 3072 | 92.9% | 95.8% | 96.0% |
| 合出 6144 | 59.3% | 65.2% | **66.5%** |
| 合出 12288 | 5.6% | 6.0% | **7.2%** |
| 平均得分 | 561,463 | 604,132 | **622,923** |

提升主要来自规则本身：奖励牌来得均匀，两张之间最多隔 41 张。知道周期后平均分再高 1.88 万（Holm p=0.041）；6144（+1.3 个百分点）和 12288（+1.1 个百分点）单项不显著。网页实际下载的 float16 权重另测 2048 局为 65.1% / 6.7%，差别不显著。用不用周期，JS 与 C++ 在 320 个局面上的走法都完全一致，知道周期的搜索也不更慢。

## V31 发布成绩

以下为旧规则（每张独立 1/21 出奖励牌）下的成绩。

规则和引擎与下文相同。用原生 C++ 评测实际发布到网页的权重（16 位浮点残差），从标准开局玩到 12288 或死亡，两组使用相同的 2048 个开局种子。

| 指标 | 原网页 AI（V23） | V31（发布版） |
|---|---:|---:|
| 合出 3072 | 87.5% | 92.9% |
| 合出 6144 | 790/2048（38.6%） | **1215/2048（59.3%）** |
| 合出 12288 | 79/2048（3.9%） | **115/2048（5.6%）** |
| 平均最终得分 | 438,894 | **561,463** |

V31 的 95% Wilson 区间：6144 为 **57.2%–61.4%**；12288 为 **4.7%–6.7%**。三个主要指标经 Holm 校正后均显著（6144 p=10⁻⁴⁴，12288 p=0.009，得分 p=3×10⁻³³）。12288 的提升来自更多对局走到了 6144：一旦合出 6144，两个 AI 之后合出 12288 的比例都约为 10%（V23 79/790，V31 115/1215）。到目前为止，针对第 3 段的实验（V27、V31、[V32](RL-V32-STRONG.md)）都没能提高这个比例。提升来自第 1–3 段新增的 5 格残差表（V29–V31）：只继续训练 4 格表没有提升，加大模式后才有。320 个抽样局面上 JS 与 C++ 的走法完全一致；桌面 Chromium 平均每步 5.4 ms（P95 9.0 ms）。

## V24 整局验收（上一版）

遵循社区逆向确认的现代 Threes 核心规则，采用标准九张牌开局。使用原生 C++，从开局玩到合出 12288 或死亡，新旧两组使用相同的 1024 个开局种子。

| 指标 | 项目改进前 AI | V23 模型 + 五层搜索 |
|---|---:|---:|
| 合出 1536 | 93.8% | 98.8% |
| 合出 3072 | 65.4% | 86.2% |
| 合出 6144 | 114/1024（11.1%） | **400/1024（39.1%）** |
| 合出 12288 | 0/1024 | **31/1024（3.0%）** |
| 平均最终得分 | 227,400 | **432,649** |

95% Wilson 区间：6144 为 **36.1%–42.1%**；12288 为 **2.1%–4.3%**。相对于项目旧 AI 的三个主要指标经 Holm 校正后均显著。此表是项目内部基线比较，不是对全部公开 AI 的统一排名。

[复现说明](docs/REPRODUCING.md) · [V24 报告](RL-V24-ACCEPTANCE.md) · [评测协议](training/v24-acceptance/protocol.json) · [逐局记录](training/v24-acceptance/games-NEW.jsonl) · [公开结果对照](docs/COMPARISONS.md)

网页有 160 ms 搜索软预算；V24 原生 NEW 组不设这个时间上限，每步完整完成五层。较慢设备可能只完成较浅搜索。成绩来自本仓库引擎，尚未在官方 App 上实测。部分训练实验按 CPU 时间停止，不同硬件不保证重训得到相同权重；仓库保留被评测的权重和哈希。

## 本地运行

需要 Python 3 提供静态服务；测试建议使用 Node.js 22。无需 npm 安装或构建步骤。

```sh
git clone https://github.com/Theonefkguy/threes-meadow-ai.git
cd threes-meadow-ai
python3 -m http.server 8000 --bind 127.0.0.1 --directory dist
```

访问 http://localhost:8000。请通过 HTTP 服务打开，避免直接双击 HTML 导致模块 Worker 和模型加载失败。

```sh
node --test tests/*.test.mjs
python3 scripts/verify-release.py
```

## 工程结构

- `dist/`：可直接编辑的网页代码、样式和模型。
- `training/`：训练与评测代码、协议、历史实验数据。
- `tests/`：规则、模型、搜索、输入与 AI 生命周期测试。
- `docs/`：复现、对照和发布说明。
- `.github/workflows/pages.yml`：先测试、校验，再仅发布 `dist/`。

当前模型（V31）第 0 段沿用 V4；第 1–3 段（最大牌 1536、3072、6144 以上）为 4 格表加 5 格残差表，用并行 TD 学习训练（V30、V31）。AI 只使用棋盘、预告候选及通过公开历史推断的剩余牌数，不读取隐藏牌序。[算法历史](AI.md)与[规则说明](RULES.md)保留在仓库中。
