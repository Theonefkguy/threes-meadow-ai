# 关键局面定向测试

语言：C++17 搜索与模拟，Python 3 调度和汇总。复用冻结的 V7 价值模型和完整搜索，不修改网页或旧实验，不创建自动任务。

## 设计与文件

- `experiment.cpp collect`：四层从新局玩到死亡，逐步输出棋盘、合法动作、隐藏剩余牌堆、公开预告及概率、实际动作与落牌、PRNG 状态、下一棋盘。死亡前回溯 N 步，默认 25（可选 20–30），每个来源局只取一个起点。
- `experiment.cpp test`：每个起点预生成三条外生随机记录；每条记录供四层、五层分别读取。最多续玩 75 步，不必下完整局。
- `run.py`：显式运行采集、测试、汇总；默认 18 起点、3 次重复、2 并发。配置与模型/程序哈希被冻结，改配置必须使用新目录。已完成任务可跳过，未完成配对会重算。
- `report.py`：校验两侧每步实际牌值等于同一 tape 对应前缀，输出逐起点表格、整体脱困率、截断平均存活步数、CPU 时间。

## 固定落牌的精确定义

同种子本身不够：分支可能消耗不同次数的随机数、奖励牌依赖最高牌、合法落点依赖动作。本实现预生成并保存牌值、公开预告和独立落点随机数；分支都读 tape[t]，不能跳过或重抽。牌值严格相同，落点用同一 [0,1) 数映射各自合法入口。两个方向不同的棋盘不能强求同一绝对落点，否则可能非法。

为保证牌值相同，奖励牌分布冻结在截取点最高牌，剩余普通牌按起点牌堆组成重洗；第一次预告不变。搜索仍使用原模型的原版随机假设，因此这是受控环境下对原搜索的诊断，不是原版分布无偏评测。隐藏 tape 不传入搜索。轨迹的 board/deck/spawn 数字为内部 rank：1→1、2→2、3→3、4→6、…；报告已转换真实牌值。replay 中 rngBefore 为 tape 生成 seed，不是原版逐步 PRNG 状态；逐步随机信息以 tape 行号为准，隐藏 deck 字段不用于续玩。

## 危险、可救与指标

回溯 25 步避免只测试最后一两步，起点必须存在合法动作，但这不是“必然有救”的数学保证。固定所有起点，不能在看了五层表现后删掉两边均失败的起点。三套牌序用于降低随机性，起点仍是独立单位。默认脱困=75 步后仍存活，另外记录最大空格数；截断存活步数不可解释为真实最终寿命，最大牌也是测试窗口内最大牌。

## 运行（仓库根目录）

```sh
python training/critical-depth/run.py collect --cases 18 --back 25
python training/critical-depth/run.py test --cases 18 --back 25
python training/critical-depth/run.py report --cases 18 --back 25
```

也可 `all` 顺序执行；`--horizon 75 --repeats 3 --workers 2 --seed 736210 --out 路径` 可配置。Ctrl+C 停止；没有后台重启机制。所有阶段须使用相同参数。输出 `trajectory-*.jsonl`、`snapshot-*.txt`、`source-*.json`、`tape-*.txt`、`replay-*.jsonl`、`result-*.json`、`summary.csv`、`report.md`。
